# 에이전트 작업 환경

이 문서는 타일앤바스플러스 프로젝트에서 Codex/AI 에이전트가 일관되게 작업하기 위한 운영 가이드입니다.

## 기본 원칙

1. 고객 화면에는 내부 브랜드 정보가 노출되면 안 됩니다.
2. 관리자/내부 화면에서는 브랜드를 최상위 필터로 사용합니다.
3. 이미지 검색은 선택된 규격과 표면/마감을 절대 필터로 사용합니다.
4. 상품 DB 변경은 `data/products.json`, `products-db.js`, 관련 정규화 스크립트의 관계를 확인한 뒤 진행합니다.
5. 기존 사용자 변경사항을 되돌리지 않고, 요청 범위에 맞는 파일만 수정합니다.

## 주요 파일

| 경로 | 역할 |
| --- | --- |
| `AGENTS.md` | 에이전트가 반드시 따라야 하는 프로젝트 정책 |
| `README.md` | 앱 실행, Supabase 연결, 화면 구조, 검증 명령 |
| `server.js` | 로컬 API 서버와 저장/조회 로직 |
| `app.js` | 프론트엔드 화면 동작 |
| `index.html` | 앱 HTML 셸 |
| `styles.css` | 앱 스타일 |
| `data/products.json` | 상품 DB 원본 |
| `products-db.js` | 브라우저용 상품 DB 번들 |
| `scripts/` | 가져오기, 정규화, 감사, 검색 시뮬레이션 도구 |

## 실행

```powershell
npm.cmd start
```

브라우저에서 `http://localhost:4173`을 엽니다.

## 검증

```powershell
npm.cmd run check
```

코드 변경이 작을 때도 최소한 변경한 JavaScript 파일은 `node --check`로 확인합니다. DB 구조나 검색 로직을 바꾼 경우에는 전체 `check`를 우선 사용합니다.

## 작업 전 체크리스트

1. `AGENTS.md`를 읽고 내부 브랜드/이미지 검색 정책을 확인합니다.
2. `git status --short`로 기존 변경사항을 확인합니다.
3. 관련 파일을 `rg`로 찾아 기존 패턴을 먼저 파악합니다.
4. 고객용 기능인지 관리자용 기능인지 구분합니다.
5. 필요한 경우 `README.md`와 `docs/`의 기존 사양을 확인합니다.

## 작업 후 보고

작업 완료 시 아래 내용을 짧게 보고합니다.

1. 변경한 파일
2. 핵심 변경 내용
3. 실행한 검증 명령과 결과
4. 검증하지 못한 부분 또는 남은 위험

## 금지 사항

1. 고객 화면, 고객 API, 고객 URL에 내부 브랜드/공급사/마진/품질 등급을 노출하지 않습니다.
2. 고객 검색이 내부 브랜드 코드나 내부 브랜드명으로 매칭되게 만들지 않습니다.
3. 이미지 검색에서 규격 또는 마감 조건을 자동으로 완화하지 않습니다.
4. 관련 없는 파일 정리, 대규모 리팩터링, 임의 포맷팅을 함께 하지 않습니다.
